# PM任务处理指南

本文档说明如何在单元测试中处理PM（项目管理）任务，适用于第2、3、4章的场景。

---

## 📋 适用场景

| 章节 | 场景 | 涉及内容 |
|------|------|---------|
| **第2章** | 首次创建单元测试 | 配置 `related_task_number` 参数 |
| **第3章** | 已有Excel新增方法 | 配置 `PM_TASK_DESC` 和 `RELATED_TASK_NUMBER` |
| **第4章** | 修改单元测试报错 | 参考PM任务修复断言 |

## 🎯 PM问题号格式

### 格式说明

| 问题类型 | 格式 | 示例 |
|---------|------|------|
| **工作任务** | `{项目}-T-{编号}` | `YYY-T-17678` |
| **特性需求** | `{项目}-MF-F-{编号}` | `YYY-MF-F-1846` |

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| **{项目}** | 项目编码，大写字母 | YYY, PROJ, ABC |
| **{编号}** | 数字编号 | 17678, 1846 |
| **T** | 工作任务标识 | 固定标识 |
| **MF-F** | 特性需求标识 | 固定标识 |

---

## 🔄 执行流程

```
用户提示词包含PM问题号
    ↓
判断问题类型
    ├─ 工作任务（-T-）→ 调用 pm_get_worktask
    └─ 特性需求（-MF-F-）→ 调用 pm_get_feature
    ↓
获取任务详情
    ↓
提取测试场景和断言要求
    ↓
从描述中提取包含 -MF- 的值 ⭐
    ├─ 正则表达式：\b[A-Z]+-MF-[^,，\s]+\b
    └─ 提取完整的编号：YYY-MF-F-2702、PROJ-MF-F-1234
    ↓
填充到Excel的relatedTask列 ⭐
    └─ 格式：PM任务号,值1,值2,...
    ↓
用于配置 test_case_count 和完善测试用例
```

---

## 🔧 获取方法

### MCP工具调用

| 问题类型 | 工具方法 | 输入参数 | 返回内容 |
|---------|---------|---------|---------|
| **工作任务** | `pm_get_worktask` | PM问题号 | 任务描述、测试场景 |
| **特性需求** | `pm_get_feature` | PM问题号 | 功能描述、验收标准 |

### 调用示例

```bash
# 工作任务
pm_get_worktask("YYY-T-17678")

# 特性需求
pm_get_feature("YYY-MF-F-1846")
```

## 📝 信息提取

从PM任务描述中提取以下信息：

### 1. 测试场景列表

**识别规则**：
- 编号格式：`1. xxx 2. xxx 3. xxx`
- 场景描述：每个编号后的文本
- 测试目标：新增/编辑/删除/查询等

**提取方法**：
```
原始描述：
1. 产品管理，新增产品。（断言：允许新增）
2. 产品管理，编辑产品。（断言：不允许编辑已发布产品）

提取结果：
场景1: 产品管理-新增产品（断言：允许新增）
场景2: 产品管理-编辑产品（断言：不允许编辑已发布产品）
```

### 2. 预期结果/断言

**常见断言类型**：

| 断言关键词 | 含义 | 测试验证 |
|-----------|------|---------|
| **允许** | 操作可以执行 | 断言方法执行成功 |
| **不允许** | 操作被拒绝 | 断言抛出异常或返回错误 |
| **成功** | 操作成功完成 | 断言返回值正确 |
| **失败** | 操作失败 | 断言抛出异常 |
| **返回true/false** | 方法返回布尔值 | 断言返回值 |
| **抛出异常** | 方法抛出异常 | 断言异常类型 |

### 3. 业务规则

**常见业务规则类型**：

| 规则类型 | 示例 | 测试场景 |
|---------|------|---------|
| **权限控制** | 只有管理员可以删除 | 测试不同角色的操作权限 |
| **数据校验** | 名称不能为空 | 测试边界条件 |
| **业务逻辑** | 已发布产品不能编辑 | 测试业务约束 |
| **状态约束** | 只有草稿状态可以修改 | 测试状态流转 |

## 📄 PM任务描述模板

### 通用模板

```
故事点：{项目}-MF-F-{编号}
1. {功能模块}，{操作描述}。（断言：{预期结果}）
2. {功能模块}，{操作描述}。（断言：{预期结果}）
3. {功能模块}，{操作描述}。（断言：{预期结果}）
...
```

### 填写规范

| 参数 | 格式 | 示例 |
|------|------|------|
| **{项目}** | 项目编码 | YYY, PROJ |
| **{编号}** | 数字 | 1234 |
| **{功能模块}** | 功能名称 | 产品管理, 订单管理 |
| **{操作描述}** | 操作说明 | 新增产品, 编辑订单 |
| **{预期结果}** | 断言描述 | 允许, 不允许, 成功, 失败 |

### 完整示例

```
故事点：PROJ-MF-F-1234
1. 产品管理，新增产品。（断言：允许新增）
2. 产品管理，编辑产品名称。（断言：允许编辑）
3. 产品管理，编辑已发布产品。（断言：不允许编辑已发布产品）
4. 产品管理，删除未使用产品。（断言：允许删除）
5. 产品管理，删除已使用产品。（断言：不允许删除已使用产品）
6. 产品管理，复制产品。（断言：允许复制）
7. 产品管理，查询产品列表。（断言：返回列表不为空）
```

## ⚙️ 脚本配置示例

### test_case_generator.py（第2章）

```python
# ========== 必填配置 ==========
sub_id = "PO"
class_name = "com.yonyou.biz.mm.xxx.XxxService"
method_names = ["execute"]
project_root = "{项目根目录}"

# ========== 可选配置 ==========
attr = Attr(
    gen_java=True,
    gen_xlsx=True,
    test_case_count=10,                    # 测试用例数量（根据PM场景数量设置）
    related_task_number="{PM问题号}"       # PM问题号，脚本会自动查询MCP并填充完整值 ⭐
)
```

**使用说明**：
- 将 `{PM问题号}` 替换为实际的PM问题号
- `test_case_count` = 边界测试场景数 + PM任务场景数
- **自动填充逻辑**：
  1. 脚本会自动调用MCP查询PM任务详情
  2. 从描述中提取包含 `-MF-` 的值
  3. 组合 relatedTask = "PM任务号,值1,值2,..."

### update_test_excel.py（第3章）

#### 简单模式

```python
# ===== 简单模式配置 =====
EXCEL_PATH = r'{项目根目录}/mock-data/{子系统}/20_testcase/{模块路径}/{类名}Test.tc.xlsx'
TARGET_METHOD_NAME = "{方法名}"
TARGET_CLASS_NAME = "{被测试类全限类名}"
SUB_ID = "{子系统}"

```

#### 完整模式（推荐）

```python
# ===== 完整模式配置 =====
EXCEL_PATH = r'{项目根目录}/mock-data/{子系统}/20_testcase/{模块路径}/{类名}Test.tc.xlsx'
TARGET_METHOD_NAME = "{方法名}"
TARGET_CLASS_NAME = "{被测试类全限类名}"
SUB_ID = "{子系统}"

# PM任务描述（按模板格式填写）
PM_TASK_DESC = """
故事点：{项目}-MF-F-{编号}
1. {功能模块}，{操作描述}。（断言：{预期结果}）
2. {功能模块}，{操作描述}。（断言：{预期结果}）
...
"""

# PM问题号
RELATED_TASK_NUMBER = "{PM问题号}"
```

**使用说明**：
- 完整模式会自动生成边界测试 + PM场景
- `relatedTask` 列会自动填充：
  - 边界测试：空
  - PM场景：自动查询MCP并填充完整值（PM任务号 + 包含-MF-的值）

## 📊 relatedTask列填充规则

### 填充逻辑（新）⭐

**执行步骤**：
```
步骤1：获取PM任务号（例如：YYY-T-17678）
    ↓
步骤2：通过 MCP 查询 PM 任务信息
    ├─ 工作任务（-T-）→ 调用 pm_get_worktask
    └─ 特性需求（-MF-F-）→ 调用 pm_get_feature
    ↓
步骤3：从查询结果的描述中提取包含 "-MF-" 的值
    ├─ 提取规则：完整编号，例如 YYY-MF-F-2702、PROJ-MF-F-1234
    ├─ 识别方式：正则表达式 \b[A-Z]+-MF-[^,，\s]+\b
    └─ 全部提取：如果存在多个包含 "-MF-" 的值，全部提取
    ↓
步骤4：组合 relatedTask 值（用英文逗号分割）
    └─ relatedTask = "PM任务号,值1,值2,..."
```

### 填充规则表

| 场景类型 | relatedTask值 | 说明 |
|---------|--------------|------|
| **PM任务场景** | `{PM任务号},{包含-MF-的值}` | 优先使用描述中的特性编码/故事点 |
| **边界测试** | 空 | 不填写，留空 |
| **异常处理** | 空 | 不填写，留空 |
| **正常流程** | 空 | 不填写，留空 |

### 提取示例

#### 示例1：描述中包含特性编码
```
提示词：PM任务：YYY-T-17678

MCP查询结果描述：
"特性编码：YYY-MF-F-2702，其他信息..."

提取结果：
- 包含 -MF- 的值：YYY-MF-F-2702

relatedTask = "YYY-T-17678,YYY-MF-F-2702"
```

#### 示例2：描述中包含故事点
```
提示词：PM任务：YYY-T-17678

MCP查询结果描述：
"故事点：PROJ-MF-F-1234，其他信息..."

提取结果：
- 包含 -MF- 的值：PROJ-MF-F-1234

relatedTask = "YYY-T-17678,PROJ-MF-F-1234"
```

#### 示例3：描述中包含多个值
```
提示词：PM任务：YYY-T-17678

MCP查询结果描述：
"特性编码：YYY-MF-F-2702，故事点：PROJ-MF-F-1234，其他：ABC-MF-001"

提取结果：
- 包含 -MF- 的值：YYY-MF-F-2702, PROJ-MF-F-1234, ABC-MF-001

relatedTask = "YYY-T-17678,YYY-MF-F-2702,PROJ-MF-F-1234,ABC-MF-001"
```

#### 示例4：描述中无包含 -MF- 的值
```
提示词：PM任务：YYY-T-17678

MCP查询结果描述：
"其他信息，无特性编码或故事点..."

提取结果：
- 包含 -MF- 的值：无

relatedTask = "YYY-T-17678"
```

### 正则表达式

**提取包含 -MF- 的值**：
```python
import re

# 正则表达式
pattern = r'\b[A-Z]+-MF-[^,，\s]+\b'

# 示例
description = "特性编码：YYY-MF-F-2702，故事点：PROJ-MF-F-1234"
matches = re.findall(pattern, description)
# 结果：['YYY-MF-F-2702', 'PROJ-MF-F-1234']
```

### 关键规则

| 规则 | 说明 |
|------|------|
| **格式** | 用英文逗号 `,` 分割 |
| **必填项** | PM任务号（第一个值） |
| **可选项** | 包含 `-MF-` 的值（特性编码或故事点） |
| **识别规则** | 从描述中提取包含 `-MF-` 的完整编号 |
| **多值情况** | 如果存在多个，全部添加 |

## 🎯 核心价值

### 对测试质量的价值

- ✅ **确保测试完整性**：覆盖PM任务中的所有场景
- ✅ **保证断言准确性**：断言与业务需求一致
- ✅ **提升测试质量**：避免遗漏关键测试场景
- ✅ **便于追溯**：测试用例与需求文档关联

### 对开发效率的价值

- ✅ **减少沟通成本**：PM任务描述明确测试需求
- ✅ **提高开发效率**：自动生成测试用例
- ✅ **降低维护成本**：relatedTask列便于需求变更时定位
- ✅ **统一测试标准**：所有测试用例遵循相同的规范
