# 技术博客写作助手

从指定路径加载写作规范，辅助撰写技术博客文章。

## 触发条件

TRIGGER when:
- 用户说 `/jc-techblog` 或 `/技术博客`
- 用户请求"按博客规范写作"
- 用户说"帮我写技术文章"
- 用户提供技术主题需要撰写文章

## 规范文件路径

`/Users/jinchen/Documents/github/jc-blog/docs/语言/写作/博客写作规范.md`

## 执行协议

### Phase 1: 加载规范

1. Read 规范文件路径
2. 解析规范内容，提取：
   - Markdown 格式规范（标题、列表、代码、链接等）
   - 内容结构规范（标准模板）
   - 写作风格要求
   - 自动化执行指令

### Phase 2: 理解用户意图

1. 询问用户文章主题（如已提供则跳过）
2. 确认文章类型：
   - 教程类
   - 踩坑/经验类
   - 对比/评测类
   - 其他（自定义结构）

### Phase 3: 写作辅助

根据用户提供的素材或提纲，按照规范撰写文章：

1. **自动格式化**：
   - H1 仅用于文章总标题
   - 标题层级不跳级
   - 中英文之间加空格
   - 代码块指定语言
   - 图片添加 alt 文本

2. **结构验证**：
   - 包含背景与动机
   - 核心内容分层展开
   - 代码示例完整可运行
   - 结尾有总结和参考资源

3. **风格检查**：
   - 使用主动语态
   - 用"你"与读者对话
   - 避免口语化和废话
   - 代码必须可验证

### Phase 4: 输出模式

**默认模式**：直接返回格式修正后的 Markdown 源码

**润色模式**（用户说"润色"）：
- 优化表达流畅度
- 保持用户语气
- 用 [建议] 标注改动

**检查模式**（用户说"检查"）：
- 输出格式问题清单
- 分级标注：严重、建议、可选

## 输出要求

- 文末添加 [格式修正摘要] 列出改动
- 不添加评价性内容
- 不重写用户核心观点
- 不改变代码逻辑

## 示例用法

```
用户: /jc-techblog
助手: 我已加载博客写作规范。请告诉我你要写的文章主题？

用户: Python 异步编程
助手: 好的，我们将写一篇关于 Python 异步编程的教程类文章。
      请提供以下信息：
      1. 文章面向的读者水平？
      2. 想覆盖的核心内容？
      3. 是否有具体代码示例？
```
